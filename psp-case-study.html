01 • BUSINESS CONTEXT

Project Overview & Data Challenge

Daily power grid analysis requires reliable information about peak demand and power consumption. The source information arrives in Excel files, while analytical reporting requires structured, consistent and historical datasets.

The Challenge

Source files needed to be discovered, downloaded, converted and prepared before they could be used for analytical processing. Historical records also needed to be maintained as new daily data became available.

The Engineering Solution

A multi-stage solution using Python, Pandas, PySpark, Delta Lake, Dataflow Gen2 and Power BI was implemented to automate data preparation, historical consolidation and reporting.

03 • NOTEBOOK 01 • DATA INGESTION

How Excel (.xls) Files Are Converted into CSV

This is the first and one of the most important engineering stages of the project. The source data is available as dated Excel files. Instead of manually downloading and converting them, the notebook automates the entire process.

Step 1 — Prepare Python Libraries

The notebook imports the libraries required for HTTP requests, Excel processing, date calculations, file management and error handling.

Notebook 1 — Imports PYTHON 
import requests
import pandas as pd
from datetime import datetime, timedelta
import os
import time
import urllib3
from requests.exceptions import RequestException

What each library does

  • requests: Sends HTTP requests to retrieve Excel files.
  • pandas: Reads Excel workbooks and converts data into CSV.
  • datetime: Calculates dates and formats filenames.
  • os: Creates directories, checks files and removes temporary files.
  • time: Adds short delays between download attempts.
  • urllib3: Handles the SSL warning configuration used in the notebook.

Step 2 — Configure HTTP Request Headers

A reusable HTTP session is configured with request headers. The notebook uses these headers when attempting to retrieve the source Excel file.

Notebook 1 — Request Configuration PYTHON 
urllib3.disable_warnings(
    urllib3.exceptions.InsecureRequestWarning
)

HEADERS = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)",
    "Accept": "application/vnd.ms-excel,application/octet-stream,*/*",
    "Connection": "keep-alive"
}

session = requests.Session()
session.headers.update(HEADERS)

Why use a Session?

A Requests Session allows the notebook to reuse configured headers across multiple HTTP requests. This is useful because the notebook checks multiple possible source file identifiers for each date.

Security consideration

The original implementation uses verify=False and suppresses SSL warnings. This disables certificate verification for those requests. It is a security trade-off, not a recommended default for a production implementation. A public portfolio should describe the actual behavior honestly.

Step 3 — Create Lakehouse File Directories

Two directories are prepared inside the Fabric Lakehouse Files area. One stores downloaded Excel files temporarily; the other stores converted CSV files.

Notebook 1 — File Paths PYTHON 
xls_dir = "/lakehouse/default/Files/xls"
csv_dir = "/lakehouse/default/Files/csv"

os.makedirs(xls_dir, exist_ok=True)
os.makedirs(csv_dir, exist_ok=True)

today = datetime.today()

Directory responsibilities

  • Files/xls: Temporary location for the downloaded Excel workbook.
  • Files/csv: Destination for converted CSV files used by subsequent processing.
  • exist_ok=True: Prevents an error when the directories already exist.

Step 4 — Implement CSV Retention

The notebook checks the CSV directory and removes dated CSV files older than three days. This controls the amount of recent converted source data retained in the working directory.

Notebook 1 — Retention Logic PYTHON 
for file in os.listdir(csv_dir):
    if not file.endswith(".csv"):
        continue

    try:
        file_date = datetime.strptime(
            file.replace(".csv", ""),
            "%d.%m.%y"
        )

        if (today - file_date).days > 3:
            os.remove(os.path.join(csv_dir, file))
            print(f"Deleted old CSV: {file}")

    except ValueError:
        pass

How this works

  1. Lists files present in the CSV directory.
  2. Ignores files that do not have the CSV extension.
  3. Extracts the date from filenames such as 25.10.26.csv.
  4. Compares the file date with the current date.
  5. Deletes files whose age is greater than three days.

Step 5 — Build the Date-Based Download Function

The core function is process_date(). It receives a target date, constructs the expected file name, checks whether a converted CSV already exists, and searches for the matching Excel source.

Notebook 1 — Date and Filename Preparation PYTHON 
def process_date(target_date):

    date_part = target_date.strftime("%d.%m.%y")
    year = target_date.strftime("%Y")
    month = target_date.strftime("%m")

    xls_path = f"{xls_dir}/{date_part}.xls"
    csv_path = f"{csv_dir}/{date_part}.csv"

    if os.path.exists(csv_path):
        print(f"CSV already exists for {date_part}, skipping")
        return True

Example of date formatting

Variable Example Purpose
target_date 25 October 2026 Input date
date_part 25.10.26 Filename date
year 2026 URL folder
month 10 URL folder

If the CSV for the requested date already exists, the function returns without downloading and converting the Excel file again.

Step 6 — Discover and Download the Excel File

This is an important part of the ingestion logic. The notebook iterates through possible numeric identifiers from 100 to 999 and constructs a candidate URL for each identifier.

Notebook 1 — Source File Discovery PYTHON 
for num in range(100, 1000):

    url = (
        f"https://webcdn.grid-india.in/files/grdw/"
        f"{year}/{month}/{date_part}_NLDC_PSP_{num}.xls"
    )

    try:
        r = session.get(
            url,
            timeout=30,
            verify=False
        )

        if r.status_code == 200 and len(r.content) > 1000:

            with open(xls_path, "wb") as f:
                f.write(r.content)

            # Excel conversion follows here

    except RequestException as e:
        print(f"Network issue: {e}")
        time.sleep(0.5)
        continue

    time.sleep(0.3)

What happens during discovery?

  1. The notebook generates a candidate URL using year, month, date and numeric identifier.
  2. It sends an HTTP GET request to the candidate URL.
  3. It checks whether the response status is HTTP 200.
  4. It also checks that the returned content is larger than 1,000 bytes.
  5. When a candidate passes those checks, its content is written to the temporary XLS file.
  6. Network exceptions are caught, logged and retried with the next candidate.
Why is this part important?

The notebook does not assume that the source file has one fixed numeric identifier. It searches a range of possible identifiers to locate a candidate file for the requested date.

The HTTP status and file-size checks are the implemented acceptance conditions. They do not independently prove that every returned file contains the expected Excel data.

Step 7 — Convert XLS into CSV Using Pandas

Once a candidate Excel file is downloaded, Pandas reads the workbook and writes its contents to CSV. The notebook explicitly specifies the xlrd Excel-reading engine.

HTTP Response Downloaded binary content
→
Temporary XLS Saved in Lakehouse Files/xls
→
Pandas Read Excel workbook
→
CSV File Saved in Lakehouse Files/csv
Notebook 1 — Excel-to-CSV Conversion PYTHON 
with open(xls_path, "wb") as f:
    f.write(r.content)

df = pd.read_excel(
    xls_path,
    engine="xlrd"
)

df.to_csv(
    csv_path,
    index=False
)

os.remove(xls_path)

print(f"Created CSV for {date_part} (PSP {num})")
return True

Detailed explanation

1. Write the downloaded content

The HTTP response contains the downloaded file as binary content. The wb mode writes those bytes into a temporary Excel file.

2. Read the Excel workbook

pd.read_excel() loads the workbook into a Pandas DataFrame. The DataFrame represents the tabular information contained in the workbook.

3. Export the DataFrame

to_csv() converts the DataFrame into a CSV file. Setting index=False prevents Pandas from adding its DataFrame index as an extra CSV column.

4. Delete the temporary XLS

After conversion, the notebook removes the temporary Excel file from the XLS directory. The converted CSV remains available for downstream Spark processing.

Result of this stage

The source Excel workbook is converted into a dated CSV file. The CSV becomes the input for the next notebook, which performs Spark-based staging and transformations.

Step 8 — Process Recent Dates and Backfill Gaps

The notebook checks the previous eleven dates. For each date, it calls the same processing function. Existing CSV files are skipped, while missing CSV files trigger the source discovery and conversion process.

Notebook 1 — Date Processing Loop PYTHON 
for i in range(1, 12):

    check_date = today - timedelta(days=i)

    process_date(check_date)

print("Run completed.")

Important distinction

The loop checks eleven previous dates, while the CSV retention logic keeps files up to three days old. These are two separate behaviors in the actual implementation.

04 • NOTEBOOK 02 • PYSPARK STAGING

CSV Ingestion, Cleansing & Transformation

After the CSV files are prepared, the second notebook reads them using Apache Spark and creates staging Delta tables for national and state-level power data.

Step 1 — Read the CSV Files

Notebook 2 — Spark CSV Reader PYSPARK 
base_path = "Files/csv/"

df = (
    spark.read
    .option("header", "false")
    .option("inferSchema", "true")
    .csv(base_path)
)

Explanation

  • header=false tells Spark that the CSV files do not contain a header row.
  • Spark therefore assigns column names such as _c0, _c1 and _c2.
  • inferSchema=true allows Spark to infer data types from the input.
  • The CSV directory is read as the source for staging transformations.

Step 2 — Extract the Date from the Filename

Notebook 2 — Filename Metadata PYSPARK 
df = (
    df
    .withColumn("file_path", F.input_file_name())
    .withColumn(
        "filename",
        F.regexp_extract("file_path", r"([^/]+)$", 1)
    )
    .withColumn("Date_str", F.substring("filename", 1, 8))
    .withColumn("Date", F.to_date("Date_str", "dd.MM.yy"))
)

How the date extraction works

The input file path is used to obtain the filename. The first eight characters are extracted and converted into a date using the dd.MM.yy format.

For example, a filename beginning with 25.10.26 produces the date 25 October 2026.

Step 3 — Add the Ingestion Timestamp

Notebook 2 — Date Modified PYSPARK 
df = df.withColumn(
    "Date_modified",
    F.current_timestamp()
)

This adds the timestamp of the processing run to the staged records. It provides ingestion-time metadata in addition to the business date extracted from the filename.

Step 4 — Create Different Staging Datasets

The notebook selects different source columns depending on the metric being processed. It creates separate staging tables for All India, Chhattisgarh and Madhya Pradesh.

All India — Peak Demand

Uses the Energy Type, WR and Total India columns from the source CSV.

  • Filters Maximum Demand Met During the Day
  • Converts MW values to GW
  • Creates All India peak demand staging data

State — Peak Demand

Uses state and maximum demand columns. Separate filters are applied for Chhattisgarh and MP.

  • Filters the required state
  • Casts maximum demand to long
  • Converts MW to GW

All India — Power Consumption

Filters the Energy Met metric and selects regional and national energy values.

  • Filters Energy Met (MU)
  • Processes WR and Total India
  • Calculates derived GW columns as coded

State — Power Consumption

Extracts state-level energy consumption values for the required states.

  • Filters Chhattisgarh and MP separately
  • Casts MU to double
  • Creates separate state staging tables

Step 5 — Example: All India Peak Demand

Notebook 2 — Peak Demand Transformation PYSPARK 
df = df.select(
    "Date",
    "Date_modified",
    F.col("_c0").alias("Energy_Type"),
    F.col("_c3").alias("WR"),
    F.col("_c7").alias("Total_India")
)

df = df.filter(
    F.col("Energy_Type") ==
    "Maximum Demand Met During the Day (MW) (From NLDC SCADA)"
)

df = (
    df
    .withColumn("WR", F.col("WR").cast("long"))
    .withColumn("Total_India", F.col("Total_India").cast("long"))
    .withColumn("Total_India_GW", F.col("Total_India") / 1000)
    .withColumn("WR_GW", F.col("WR") / 1000)
)

Why divide by 1,000?

The source peak demand values are represented in megawatts (MW). Dividing by 1,000 converts the values into gigawatts (GW).

For example, 50,000 MW becomes 50 GW. The same conversion is applied to the regional and national values in this transformation.

Step 6 — Create State-Level Datasets

Notebook 2 — State Filtering Example PYSPARK 
df = df.select(
    "Date",
    "Date_modified",
    F.col("_c1").alias("State"),
    F.col("_c2").alias("Max_Demand")
)

df = df.filter(
    F.col("State") == "Chhattisgarh"
)

df = (
    df
    .withColumn("Max_Demand", F.col("Max_Demand").cast("long"))
    .withColumn("Peak_Demand_GW", F.col("Max_Demand") / 1000)
)

The same processing pattern is used separately for Madhya Pradesh, with the state filter changed to MP.

Step 7 — Remove Duplicates and Add Partition Columns

Notebook 2 — Deduplication and Partitioning PYSPARK 
df = df.dropDuplicates([
    "Date",
    "Date_modified",
    "State",
    "Max_Demand",
    "Peak_Demand_GW"
])

df = (
    df
    .withColumn("year", F.year("Date"))
    .withColumn("month", F.month("Date"))
)

Explanation

  • Duplicate handling is applied using the selected columns.
  • The year is extracted from the business date.
  • The month is extracted from the business date.
  • These columns are used when writing partitioned Delta tables.

Step 8 — Write Staging Delta Tables

Notebook 2 — Delta Table Write PYSPARK 
(
    df.write
    .format("delta")
    .mode("overwrite")
    .partitionBy("year", "month")
    .saveAsTable("staging.peak_demand_CG")

The same write pattern is applied to the other staging datasets, including All India peak demand, state peak demand and power consumption tables.

05 • NOTEBOOK 03 • HISTORICAL CONSOLIDATION

Delta Lake MERGE — Updating Historical Data

The third notebook consolidates staged data into the historical target tables. Instead of simply replacing the entire historical dataset, SQL MERGE operations match records using defined business keys.

Step 1 — Understand the MERGE Operation

Staging Table Recently processed data
→
Match Condition Compare business keys
→
Historical Table Update or insert records

WHEN MATCHED

When a matching business key is found, the existing historical record is updated using the latest staged values.

WHEN NOT MATCHED

When no matching record exists, a new record is inserted into the historical target table.

Step 2 — Example: All India Peak Demand MERGE

Notebook 3 — Delta SQL MERGE SQL 
MERGE INTO peak_demand_AI AS tgt
USING staging.peak_demand_AI AS src

ON tgt.Date = src.Date

WHEN MATCHED THEN UPDATE SET
    tgt.Date_modified = src.Date_modified,
    tgt.Energy_Type = src.Energy_Type,
    tgt.WR = src.WR,
    tgt.Total_India = src.Total_India,
    tgt.Total_India_GW = src.Total_India_GW,
    tgt.WR_GW = src.WR_GW

WHEN NOT MATCHED THEN INSERT (
    Date,
    Date_modified,
    Energy_Type,
    WR,
    Total_India,
    Total_India_GW,
    WR_GW,
    year,
    month
)
VALUES (
    src.Date,
    src.Date_modified,
    src.Energy_Type,
    src.WR,
    src.Total_India,
    src.Total_India_GW,
    src.WR_GW,
    year,
    month
)

How the matching works

For All India peak demand, the matching key is Date. If that date already exists in the target table, the selected values are updated. Otherwise, a new row is inserted.

Step 3 — Different Business Keys

The notebook uses different matching conditions according to the type of dataset.

Dataset MERGE Matching Key
All India Peak Demand Date
Chhattisgarh Peak Demand Date + State
MP Peak Demand Date + State
All India Power Consumption Date + Energy_Type
Chhattisgarh Power Consumption Date + State
MP Power Consumption Date + State

Step 4 — Forecast and Actual Demand

The notebook also contains a separate MERGE operation for the demand forecasting dataset. It matches records using Date and updates forecast and actual demand values.

Notebook 3 — Forecast MERGE SQL 
MERGE INTO demand_forecasting AS tgt
USING staging_demand_forecasting AS src

ON tgt.Date = src.Date

WHEN MATCHED THEN UPDATE SET
    tgt.Demand_Forecast_GW = src.Demand_Forecast_GW,
    tgt.Actual_Demand_GW = src.Actual_Demand_GW

WHEN NOT MATCHED THEN INSERT (
    Date,
    Demand_Forecast_GW,
    Actual_Demand_GW,
    year,
    month
)
VALUES (
    src.Date,
    src.Demand_Forecast_GW,
    src.Actual_Demand_GW,
    year(src.Date),
    month(src.Date)
)

Step 5 — Validate Record Counts

Notebook 3 — Count Checks PYSPARK 
spark.sql(
    "SELECT COUNT(*) FROM peak_demand_AI"
).show()

spark.sql(
    "SELECT COUNT(*) FROM staging.peak_demand_AI"
).show()

The notebook executes source and target count queries after the merge operations. These queries provide a basic way to inspect the number of records in the staging and historical tables.

Important implementation detail

Record counts alone do not prove that every record has been merged correctly. A stronger validation process would also check duplicate business keys, missing dates and mismatched values between source and target tables.

06 • NOTEBOOK 04 • TABLE PARTITIONING

Creating Partitioned Historical Delta Tables

The fourth notebook creates new Delta tables with explicit schemas and year/month partitioning. Existing historical data is then inserted into these new tables.

Step 1 — Create a New Partitioned Table

Notebook 4 — Table Definition SQL 
CREATE TABLE IF NOT EXISTS peak_demand_AI_new (
    Date DATE,
    Date_modified TIMESTAMP,
    Energy_Type STRING,
    WR DOUBLE,
    Total_India DOUBLE,
    Total_India_GW DOUBLE,
    WR_GW DOUBLE,
    year INT,
    month INT
)
USING DELTA
PARTITIONED BY (year, month)

What does partitioning mean?

Partitioning organizes table data according to specified column values. Here, the partition columns are year and month.

This creates a date-oriented organization for the stored data. It can help queries that filter by those partition columns avoid scanning unrelated partitions.

Step 2 — Insert Historical Data

Notebook 4 — Historical Data Migration SQL 
INSERT INTO peak_demand_AI_new
SELECT
    Date,
    Date_modified,
    Energy_Type,
    WR,
    Total_India,
    Total_India_GW,
    WR_GW,
    year(Date) AS year,
    month(Date) AS month
FROM peak_demand_AI

What happens here?

  1. The new table is created with an explicit schema.
  2. The historical target table is used as the source.
  3. Year and month are derived from the Date column.
  4. Historical records are inserted into the new partitioned table.
  5. Record counts are queried to inspect the source and destination.

Code review before publishing

In the supplied Notebook 4 code, the All India power consumption INSERT statement contains Total_India_GW DOUBLE inside its SELECT list. That is not a valid SELECT expression as written. The intended expression appears to be the existing Total_India_GW column. Verify the executed version before presenting this SQL as production-ready code.

07 • DATA INTEGRATION
