01 / OVERVIEW

Project Overview

This project automates the movement of meeting and event information from a collaboratively maintained Excel workbook into Outlook Calendar.

Five team members contribute event information to an online Excel workbook. Instead of generating calendar events directly from Excel, an intermediate SharePoint List is used to store and manage the event records.

Microsoft Power Automate connects these systems through two independent cloud flows. The first synchronizes Excel records with SharePoint on a scheduled basis. The second responds to SharePoint item creation or modification and processes the corresponding Outlook calendar event.

02 / BUSINESS PROBLEM

Why Was This Automation Needed?

01

Collaborative Data Entry

Multiple team members maintain event information in a shared Excel workbook. The workbook acts as the common input source for meeting data.

02

Direct Excel Integration Complexity

Generating Outlook calendar events directly from the collaborative Excel source introduced complications in the workflow.

03

Need for a Structured Data Layer

An intermediate SharePoint List provides a separate location for maintaining synchronized event records before calendar processing.

ARCHITECTURAL DECISION

Introduce SharePoint between Excel and Outlook

Separate data synchronization from calendar event processing. This creates two independently managed automation stages instead of coupling calendar operations directly to the Excel workbook.

IMPLEMENTATION SCREENSHOT

Excel Data Synchronization Flow

FLOW 01

Power Automate workflow for reading Excel records, filtering events and synchronizing SharePoint items.

01

Read Excel Table Records

The List rows present in a table action retrieves records from the configured Excel table.

SOURCE ACTION
List rows present in a table
02

Filter Eligible Events

The Filter array action checks that StartDate is not empty and retains records whose StartDate falls within the configured 15-day lookback window.

FILTER EXPRESSION
and(
    not(empty(item()?['StartDate'])),
    greaterOrEquals(
        item()?['StartDate'],
        formatDateTime(
            addDays(utcNow(), -15),
            'yyyy-MM-dd'
        )
    )
)

This filter applies a lower date boundary. It does not independently impose an upper date boundary.

03

Process Each Filtered Record

Apply to each iterates through the filtered Excel records so that each event is checked individually.

04

Find Existing SharePoint Records

Get items searches the SharePoint List using TaskID as the matching identifier, with a Top Count of 1.

MATCHING LOGIC
TaskID eq '[Current Excel Task ID]'
05

Check Whether the Record Exists

The condition checks the number of matching SharePoint records. 

length(body('Get_items')?['value']) = 0
TRUE

Create Item

If no matching record exists, a new SharePoint item is created.

FALSE

Update Item

If a matching record exists, the existing SharePoint item is updated.

Flow 01 Outcome

Excel event information is synchronized into SharePoint using TaskID-based matching, with separate create and update operations.

06 / ARCHITECTURAL VALUE

Why Use SharePoint as the Intermediate Layer?

The main design decision is separating collaborative data entry from downstream calendar operations.

01

Separation of Responsibilities

Excel handles collaborative input, while SharePoint stores synchronized records and the second flow handles calendar operations.

02

Structured Intermediate Storage

SharePoint provides a list-based structure for maintaining event records and associated processing information.

03

Record Matching

TaskID-based matching allows the first flow to distinguish between new and existing SharePoint records.

04

Event Traceability

Storing Outlook Event ID in SharePoint establishes a reference to the corresponding calendar event.

05

Independent Automation Stages

Synchronization and calendar processing are maintained in separate cloud flows, making their responsibilities easier to understand independently.

06

Centralized Event Records

The SharePoint List acts as the intermediate record repository used by the calendar automation.

07 / TECHNICAL CONSIDERATIONS

Key Implementation Considerations

Record Identification

Matching Excel and SharePoint records using TaskID is important for avoiding duplicate SharePoint entries during repeated synchronization.

Date and Time Zone Handling

Event timestamps are converted from UTC to India Standard Time before being passed to the Outlook calendar actions.

Conditional Processing

The workflow evaluates Event ID availability, StartDate availability and event Status before proceeding through its configured processing branches.

Maintaining Event References

Writing the generated Outlook Event ID back to SharePoint provides a persistent reference for subsequent processing.
