01 / PROJECT OVERVIEW

A unified path from ingestion to reporting.

This project implements a Microsoft Fabric data engineering solution using the Wide World Importers sample scenario. It starts with source data files, lands them in a Lakehouse, transforms them into structured analytical tables, prepares a curated Gold layer and makes the data available for business reporting.

The workflow combines Fabric Data Factory, a PySpark notebook, Dataflow Gen2, pipeline orchestration, a Direct Lake semantic model and a Power BI profit report.

02 / BUSINESS SCENARIO

The challenge: fragmented data preparation.

In the WWI scenario, customer and sales data arrives from multiple business channels. The analytics team’s manual preparation process can delay reporting and create inconsistencies between business units.

↘

Manual ingestion

Source files need to be collected and loaded before they can be analyzed.

⌁

Repeated preparation

Data validation and transformation are performed as separate preparation steps.

◷

Delayed reporting

Business reporting depends on prepared and consistently modeled data.

04 / IMPLEMENTATION

Seven challenge tasks. One connected solution.

The implementation was completed in seven stages, from provisioning the Fabric workspace through delivering the final report.

01
FOUNDATION

Created the workspace and Lakehouse

Provisioned the Microsoft Fabric workspace and created the wwilakehouse Lakehouse to hold the solution data and artifacts.

Fabric workspaceLakehouseOneLake
02
INITIAL DATA LOAD

Loaded customer data and created an initial report

Loaded dimension_customer as a managed Delta table, queried customer counts by BuyingGroup through the SQL analytics endpoint, and created a semantic model and initial report.

CSVDelta tableSQL analytics endpoint
03
DATA INGESTION

Built the Data Factory ingestion pipeline

Created IngestDataFromSourceToLakehouse with a Copy data activity to ingest the WWI Parquet dataset from Azure Blob Storage into the Lakehouse Files area.

Data FactoryAzure Blob StorageParquet
04
DATA TRANSFORMATION

Transformed raw data into analytical Delta tables

Used a PySpark notebook to prepare the sales fact table, dimension tables and aggregate tables, organizing the data into a star-schema structure.

PySparkDelta LakeStar schema
05
GOLD LAYER

Created a curated sales table with Dataflow Gen2

Joined sales facts with city attributes, prepared the required fields and calculated ProfitMargin as Profit divided by TotalIncludingTax. The output was written to Gold_Sales_By_City.

Dataflow Gen2Power QueryProfit margin
06
ORCHESTRATION

Automated the workflow and configured notifications

Extended the pipeline to run the data copy, Dataflow Gen2 transformation and an Outlook success notification in sequence, then configured a daily schedule.

Pipeline orchestrationOutlook notificationScheduling
07
REPORTING

Built the Direct Lake model and Power BI profit report

Configured relationships between the sales fact and dimension tables, then created a profit report with profit by territory, fiscal month and employee.

Direct LakeSemantic modelPower BI
